# Session log — 2026-11-17

## Goal

Turn this repo (until now a static blog) into an Apple-Notes-style desktop
app for Omarchy (Linux first, macOS later) plus a blog server that publishes
flagged notes. Decisions from the user:

- One repo. The old blog lives on in `site/`.
- Only notes flagged `published: true` leave the machine.
- A hosted multi-user platform stays the long-term goal.
- The server must deploy anywhere: Cloudflare (Worker + D1) by default, or
  Node/Docker with SQLite (works behind `tailscale serve` / `funnel`).
- Writers should eventually sell reader subscriptions (planned, not built).

Full plan and phases: `docs/plan.md`.

## What was built (PRs #1, #2, #3, #5, #6, #7, merged as one stack)

- **#1 App skeleton** — blog moved to `site/`; Rust workspace with
  `crates/core` (notes as markdown files with lossless frontmatter, atomic
  writes, `.trash/`, path validation) and `app/` (Tauri 2 + Svelte 5 +
  Tiptap markdown editor, three panes, autosave, file watcher).
- **#2 Blog server** — `server/`: Hono app over a small `Db` interface with
  D1 (`worker.ts`) and `node:sqlite` (`node.ts`, `Dockerfile`) adapters;
  Bearer `CODA_TOKEN`; RSS; slug fixed at first publish.
- **#3 Publish from the app** — `[server]` in
  `~/.config/coda-writer/config.toml`; Publish/Unpublish button; trashing a
  published note takes it down.
- **#5 Search** — Ctrl+F searches every folder by reading files (no index
  yet; add SQLite only if a real folder proves slow).
- **#6 Organise** — move notes, rename/delete folders, trash view with
  restore.
- **#7 Heading titles** — a header-less note starting with `# Heading` no
  longer shows its title twice.

## Verification

- `cargo test -p coda-core` (22 tests), `server` `npm test` (11 tests),
  `app` `npm run check`.
- The app has no WebKitGTK on the Debian dev box, so it is built and driven
  under Xvfb in the Docker image `coda-writer-arch` (volumes
  `coda-writer-target`, `coda-writer-cargo`); build with
  `cargo build --release --locked -p coda-writer --features tauri/custom-protocol`.
- Worker checked with `wrangler deploy --dry-run` and a local D1; Docker
  server image `coda-writer-server` checked for persistence across restarts.
- Not yet run on a real Omarchy desktop or deployed to a real Cloudflare
  account.

## Known breakage after merge

The Cloudflare Pages project `ace` still builds from the repo root, so after
this merge https://ace-8mk.pages.dev/ serves a 404. The user accepted this;
the plan is to replace Pages with the Cloudflare Worker in `server/`. A quick
fix is to set the Pages root directory to `site`.
